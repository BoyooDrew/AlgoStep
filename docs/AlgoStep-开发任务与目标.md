#### A1. 新增图论算法（4 个）

> 新建 `algorithms/graph/` 分类目录，首页新增"图论"分类卡片。

| 优先级 | 算法 | 难度 | 可视化方案 | 要点 |
|---|---|---|---|---|
| P0 | Dijkstra 最短路 | 基础 | SVG 加权图 + 距离表 | 松弛操作，优先队列（或线性扫描），路径高亮洋红 |
| P0 | 并查集 (DSU) | 基础 | 树形结构 + 路径压缩动画 | find/union 两操作，路径压缩可视化，按秩合并 |

| P1 | 拓扑排序 | 基础 | DAG + 入度表 | BFS（Kahn 算法），入度递减，队列可视化 |

### 阶段 B：v1.2 — DP 优化 + 体验打磨

#### B1. 新增 DP 优化算法（2-3 个）

| 优先级 | 算法 | 难度 | 可视化方案 | 要点 |
|---|---|---|---|---|
| P1 | 最长递增子序列（二分优化） | 进阶 | 一维卡片 + 二分查找过程 | 基于 LIS 的 `O(n log n)` 优化，tails 数组，二分插入点 |
| P2 | 区间 DP（石子合并） | 进阶 | 二维三角网格 | `dp[i][j] = min(dp[i][k] + dp[k+1][j])`，区间枚举顺序 |
| P2 | 树形 DP（没有伞兵） | 进阶 | 树形结构 + 状态表 | `dp[u][0/1]` 选/不选，后序遍历转移 |

#### B2. 可选改进项

| 编号 | 问题 | 方案 |
|---|---|---|
| O-2 | 缺少 404 页面 | 创建 `404.html`， Surge.sh 配置 `error.html` 路由 |
| O-4 | 移动端体验未验证 | 全算法页在 375px / 414px 宽度下测试，修复布局溢出 |
| O-5 | 代码面板小屏可读性（13px 偏小） | 添加媒体查询，小屏提升至 14-15px |
| O-6 | 快排步骤密度偏高 | 引入步骤合并策略（连续无交换的 compare 合并） |
| O-14 | 0-1 背包 finish 步骤绿色阴影不一致 | 统一 finish 步骤样式，与已排序绿色一致 |

### 阶段 C：v2.0 — Spring Boot 后端 Phase 1

> 从纯前端项目演进为全栈应用，后端独立仓库或 monorepo 结构。

#### C1. 技术选型

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | 现有 HTML/CSS/JS | 增量改造，引入 fetch 调用 API |
| 后端 | Spring Boot 3.x | RESTful API |
| 认证 | JWT + BCrypt | 无状态认证 |
| 数据库 | MySQL 8.x | 学习进度持久化 |
| ORM | MyBatis-Plus | 简化 CRUD |
| 部署 | Docker + Nginx 反向代理 | 前端 Surge.sh，后端云服务器 |

2. **新建算法页必查清单**：参照参考文档第十三章"开发避坑清单"逐项检查
3. **颜色规范**：严格遵循参考文档第六章 6.3 节颜色体系，回溯统一洋红 `#ec4899`
4. **DP 表格规范**：列数 W+3、三层分离 calcDp/dp/fullDp、compare 显示 `?`
5. **路径规则**：算法页引用公共资源用 `../../`，首页用 `./`
6. **部署流程**：`git add` → `git commit` → `git push` → `npx surge . algo-step.surge.sh`（PowerShell 分步执行）
